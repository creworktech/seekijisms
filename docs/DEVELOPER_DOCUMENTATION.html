1. Technology Stack & Architectural Principles

Seekoji SMS is designed as a high-performance modern monolithic web application. It leverages Inertia.js to combine the developer productivity of Laravel 12 with the rich reactivity of React 19 without building or maintaining a separate REST GraphQL layer.

Component Framework / Library Architectural Purpose & Implementation Details
Backend Core Laravel 12.x (PHP 8.2+) Handles routing, HTTP middleware gates, database transactions, request validation, and CSRF protection.
Monolith Adapter Inertia.js 2.0 Renders server-side responses as client-side page props, eliminating REST API serialization boilerplate for page navigation.
Frontend Core React 19 Modular component tree, local state hooks, custom drawer components, and reactive UI updates.
State Engine App\Services\JobWorkflow Finite State Machine (FSM) controlling all 8 stage transitions, outcome updates, and financial rule evaluations.
Sequence Service App\Services\CounterService Provides thread-safe atomic sequence generation for work order tokens and customer IDs via database row-level locks.
Build Engine Vite 7.3 + TailwindCSS 4.0 Hot Module Replacement (HMR) development server and minified production bundles with CSS custom variables.
Database Engine MySQL 8.0 / SQLite Relational storage supporting transactions, JSON columns, soft/hard deletes, and indexed search queries.

4. Finite State Machine (FSM) Core Specifications

The central business logic engine of Seekoji SMS is implemented in App\Services\JobWorkflow. This service acts as a deterministic state machine.

Transition Execution Pipeline: When JobWorkflow::transition($job, $action, $data, $user) is called:
  1. Validates if $action is registered under current stage $job->stage. Throws HTTP 409 Conflict if illegal.
  2. Executes required data validations (e.g., estimated_budget required for fault_found). Throws HTTP 422 if payload invalid.
  3. Invokes state mutator callback to update $job->stage, $job->outcome, and financial snapshot fields inside a DB transaction.
  4. Records an immutable audit record into job_events with action name, note, actor ID, and payload.

4.1 Complete Transition Handler Registry

Current Stage Action Trigger Target Stage Set Outcome Financial & Field Rules
new assign_tester testing None Assigns tester_id. Records note.
new cancel completed cancelled Sets payable_amount = 0. Job terminated at intake.
testing ok_no_fault completed ok_no_fault Sets payable_amount = inspection_fee (or 0).
testing fault_found approval None Requires estimated_budget >= 0. Stores tester_findings.
testing not_repairable completed not_repairable Sets payable_amount = inspection_fee. Stores findings.
approval approve repair None Requires approved_amount and technician_id.
approval not_approved completed not_approved Sets payable_amount = inspection_fee (0 if waived). UI shows NO AMOUNT DUE.
repair work_done completed work_done Requires final_amount. Sets payable_amount = final_amount.

completed release_unpaid ready None Leaves is_paid = false. Moves to ready for delivery with dues.
ready deliver delivered None Requires received_by. Terminal stage transition.

5. Atomic Token Generation & Counter Service

To guarantee gapless, race-condition safe sequence numbers across concurrent user sessions, Seekoji SMS utilizes an atomic row-locking mechanism implemented in App\Services\CounterService. 

// App\Services\CounterService.php Implementation
public static function generateNextToken(): string
{
    return DB::transaction(function () {
        $prefix = Setting::get('token_prefix', 'SES');
        $counter = Counter::where('key', 'job_token')->lockForUpdate()->first();

        if (! $counter) {
            $counter = Counter::create(['key' => 'job_token', 'value' => 0]);
        }

        $counter->value += 1;
        $counter->save();

        return $prefix . $counter->value;
    });
}

5.1 Pre-Generated Token Preview API

When users open the Intake Modal, the system calls GET /api/v1/jobs/token-preview?count=N.

  • The helper previewJobTokenInfo($count) inspects current counter value V without incrementing database records.
  • Returns preview list ["SES" + (V+1), "SES" + (V+2), ...].
  • If the user closes the modal without submitting, zero counter IDs are wasted.

6. API Route Registry & Validation Specs

HTTP Method Route Endpoint Request Class / Middleware Response Payload / Action
